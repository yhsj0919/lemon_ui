# Lemon UI 架构原则

主题、设备解析和集中式尺寸系统见 [主题与尺寸架构](theme-architecture.md)。组件的统一自定义层级、插槽规则、第三方适配边界和逐控件验收表见 [自定义契约](customization-contract.md)。实现与测试同时遵守 [编码规则](coding-guidelines.md)。这些文档与本文具有同等约束力。

HyperOS 风格组件、材质、形状和悬浮层的外部实现参考及取舍见 [Miuix 参考审查](miuix-reference-review.md)。

## 设计参考

Lemon UI 以小米 HyperOS 系统 UI 作为主要视觉与交互参考，目标是在 Flutter 中形成统一、易用且可维护的 HyperOS 风格组件体系。

重点参考以下方面：

- 颜色层级、背景与表面关系。
- 圆角、留白、控件高度和内容密度。
- 字体层级、图标比例和信息强调方式。
- 按压、悬停、聚焦、选中和禁用反馈。
- 弹性、淡入淡出、缩放、位移及页面转场节奏。
- 卡片、列表、表单、导航、弹窗和系统控制组件的视觉语言。
- 模糊、半透明、阴影、高光和层级关系。
- 手机、平板及桌面形态下的响应式适配规律。

### 参考边界

设计取证按以下顺序执行：

1. HyperOS 实机页面、录屏和可重复验证的系统行为。
2. 官方公开设计资料。
3. `compose-miuix-ui/miuix` 的控件结构、默认参数和状态处理。
4. Flutter Material/Cupertino 的成熟交互机制与可访问性实现。
5. 在上述来源都不足时，采用项目内一致且可预测的明确默认值。

使用 MIUIX 参考时，应记录参考的控件或源码位置，并将结果转换为 Lemon UI
自己的语义属性、明确逻辑尺寸和独立控件主题。不得直接复制 Compose API、
Modifier 链、隐式缩放规则或与 Flutter 不匹配的实现层次。

- HyperOS 是设计参考，不直接复制系统私有代码、资源或不可授权素材。
- 不照搬其他平台的内部 API；公开 API 必须符合 Flutter 和 Dart 的使用习惯。
- 优先还原整体设计语言和交互一致性，不以逐像素复制破坏可访问性、性能或跨设备适配。
- 无法从公开界面确认的行为采用稳定、可预测且符合 Flutter 习惯的实现。
- 视觉参数应沉淀为主题和设计令牌，不能散落在控件实现中。
- 项目应明确说明其为非官方组件库，不代表或隶属于小米。

### 视觉校准

- 参考截图应尽量记录 HyperOS 版本、设备、逻辑尺寸、显示缩放和亮暗模式。
- 尺寸、颜色、透明度、圆角、阴影和动画参数通过设计令牌统一校准。
- 对核心控件建立 Golden 测试，避免后续修改破坏整体视觉一致性。
- 当不同 HyperOS 版本存在差异时，由主题或版本化令牌处理，不在控件中散布平台判断。

## 多设备适配

Lemon UI 必须同时适配手机、平板、桌面和手表。四类设备共享统一的公开控件 API、状态模型和主题体系，通过设备策略调整布局、默认尺寸、交互和视觉效果。

### 设备类型

统一定义强类型设备类别：

```dart
enum HyperDeviceType {
  phone,
  tablet,
  desktop,
  watch,
}
```

设备类型表示真实设备类别，在应用或窗口作用域首次建立时根据平台能力和初始设备信息确定，同时允许应用在 `HyperTheme` 或设备作用域中显式覆盖，便于预览、特殊设备和测试。普通窗口缩放不得改变设备类型。

- 设备探测由 `HyperTheme` 统一协调，对业务层只暴露当前离散设备类型和显式覆盖入口；应用不需要据此手工创建对应主题。
- 内置探测顺序为显式类型、自定义解析器、平台类别和移动设备初始形态。Windows、Linux 和 macOS 固定为 desktop；只有 Android 和 iOS 自动区分 phone、tablet 或 watch；其他未明确平台暂时回退 desktop。
- 手表、嵌入式窗口和特殊多窗口场景应允许应用显式确认设备类型。

### 适配原则

- 设备尺寸依据稳定的设备类型；当前窗口和可用空间另行决定页面形态，不得混用两个概念。
- 不对所有控件进行简单等比缩放，应使用明确的默认尺寸和布局策略。
- 所有设备使用相同业务 API，设备差异由主题与内部布局策略解析。
- 控件实例可以覆盖设备默认行为，但不应要求业务层为四类设备分别构建四套界面。
- 窗口尺寸变化时页面应安全更新 compact、medium 或 expanded 布局，但控件继续使用原设备类型的尺寸方案。

### 手机

- 以触摸操作、单列内容和底部导航为主。
- 保证足够的触控区域，兼顾单手操作和软键盘遮挡。
- 悬浮层优先适应窄屏并避开安全区域。

### 平板

- 支持多列、主从布局、侧栏和更宽的弹窗。
- 横竖屏及分屏状态根据实际窗口宽度动态调整。
- 触摸仍是主要输入，同时兼容键盘、鼠标和手写笔。

### 桌面

- 支持更高信息密度、可调整窗口、多栏布局和精确指针输入。
- 完整支持悬停、右键、焦点、键盘导航和快捷键。
- Menu、Popover 和 Tooltip 等优先采用锚定式悬浮层。

### 手表

- 使用简洁层级、短文本、大触控目标和低信息密度。
- 优先支持纵向滚动、滚轮或旋钮输入以及圆形安全区域。
- 默认减少大面积模糊、复杂阴影和高成本持续动画。
- 关键操作不能依赖悬停、右键或仅图形提示。

### 主题与尺寸

`HyperThemeData` 通过集中式 `HyperSizeThemeData` 为不同 `HyperDeviceType` 配置：

- 基本控件高度和触控区域。
- 页面边距、组件间距和布局断点。
- 控件与图标尺寸；字体规范由独立排版主题管理。
- 圆角、阴影、模糊和动画强度。
- 导航、弹窗和悬浮层的布局策略。

主题仍遵循既定优先级：

```text
控件实例 Style
→ 当前子树局部组件主题
→ 全局组件主题
→ 当前设备的集中式尺寸方案
→ 组件库内置 HyperOS 默认主题
```

### 测试要求

- 每个核心控件至少覆盖手机、平板、桌面和手表四类设备策略。
- 覆盖窗口动态缩放、横竖屏、分屏、文字放大和 RTL。
- 桌面覆盖鼠标、悬停、键盘和焦点；手表覆盖圆形约束及低性能视觉降级。
- Golden 测试按设备类别维护代表性视觉基准。

## 命名规范

- Dart 包名保持为 `lemon_ui`。
- 所有公开控件统一使用 `Hyper` 前缀，例如 `HyperButton`、`HyperSwitch`。
- 控件基础名称优先参考 Flutter 原生 Widget 和 Material/Cupertino 已有术语，例如 `Button`、`IconButton`、`TextField`、`Checkbox`、`Dialog`、`NavigationBar`。
- 与 Flutter 原生控件概念对应时，采用“`Hyper` + Flutter 原生名称”，不另造同义名称。例如使用 `HyperTextField`，不使用 `HyperInputBox`。
- 属性、回调、状态和控制器命名优先保持 Flutter 原生习惯，例如 `child`、`builder`、`value`、`onChanged`、`onPressed`、`enabled`、`controller`、`focusNode`。
- 构造参数的类型、是否可空及行为语义应尽量与对应 Flutter 原生控件一致，降低迁移和学习成本。
- Flutter 已有稳定命名时不得仅为了风格差异重新命名；视觉差异应由 Hyper 主题或 variant 表达。
- Flutter 没有对应概念时，才采用清晰、通用且可扩展的新名称，并在公开前检查是否与现有 Flutter 术语冲突。
- 控件对应的主题类型使用“控件名 + `ThemeData`”，例如 `HyperButtonThemeData`。
- 组件库总主题使用 `HyperTheme` 和 `HyperThemeData`。
- 公开的共享类型、控制器和服务原则上也使用 `Hyper` 前缀。
- Dart 文件使用 snake_case，并与公开类型对应，例如 `hyper_button.dart`、`hyper_button_theme.dart`。
- 内部私有类型使用下划线前缀，不为内部实现添加无意义的公开别名。

命名选择顺序：

```text
Flutter 原生公开命名
→ Material / Cupertino 规范中的稳定命名
→ UI 领域通用命名
→ HyperOS 特有概念命名
```

## 开箱即用与渐进配置

Lemon UI 必须使用尽量少的业务代码完成风格统一的界面绘制。常用场景提供完整默认行为，高级能力按需启用，不能要求调用方为普通控件重复配置主题、状态、动画或控制器。

### 零配置默认值

- 所有基础控件在只提供必要内容和回调时即可直接使用。
- 未显式提供 `HyperTheme` 时，组件库应从 Flutter `ThemeData` 和内置默认值生成可用主题。
- 默认主题必须同时覆盖颜色、字体、圆角、尺寸、间距、交互状态和动画。
- 普通用法不得强制创建 controller、focus node、animation controller 或 overlay entry。
- 可选配置为空时必须有明确且一致的回退值，不能因为缺少局部主题而无法绘制。

基础用法应保持简洁：

```dart
HyperButton(
  onPressed: save,
  child: const Text('保存'),
)
```

异步用法只增加异步回调：

```dart
HyperButton(
  onPressed: saveAsync,
  child: const Text('保存'),
)
```

### 一处配置，全局生效

- 应用只需在根部配置一次 `HyperTheme`，所有 Hyper 控件自动继承。
- `HyperThemeData` 应提供基于主题色或 Flutter `ColorScheme` 创建完整主题的便捷构造方式。
- 修改全局主题色、圆角、基本高度或动画规范后，所有未单独覆盖的控件自动同步。
- 小尺寸或比例敏感控件是例外：其识别性形状由控件自身默认值和对应控件主题管理，不直接同步全局基础圆角。
- 局部区域可以嵌套 `HyperTheme` 覆盖部分配置，无需复制完整主题对象。

建议用法：

```dart
HyperTheme(
  data: HyperThemeData.fromSeed(
    seedColor: const Color(0xFFFFD54F),
  ),
  child: const App(),
)
```

### 颜色语义与真实页面层级

颜色槽位表达用途，不表达某个控件或某个固定色值。默认亮色方案以 HyperOS
真实页面的视觉关系为基准：浅灰页面、白色内容/弹层、中性灰次要操作、蓝色
主要操作，以及独立的半透明遮罩。

| 语义 | 用途 |
| --- | --- |
| `primary` / `onPrimary` | 确认、选中和主要操作 |
| `background` / `onBackground` | 页面最底层及其默认正文 |
| `surface` / `onSurface` | 卡片等普通内容表面 |
| `surfaceElevated` / `onSurfaceElevated` | Dialog、Menu、BottomSheet 等悬浮表面 |
| `surfaceMuted` / `onSurfaceMuted` | 取消按钮、弱选中块等中性操作 |
| `textPrimary/Secondary/Tertiary` | 标题、正文/说明、弱提示三级文字 |
| `outline` | 边框和分隔线 |
| `stateLayer` | 悬停、按压和聚焦的统一中性交互遮罩基色 |
| `scrim` | 悬浮层背后的页面遮罩 |

种子色只生成强调色族，不得顺带染色页面背景、中性表面或文字。组件应直接读取
与用途对应的语义槽位；禁止在组件内部用 `primary.withOpacity(...)` 临时制造
中性色。所有槽位均可在全局 `HyperColorScheme.copyWith` 中显式替换。

控件默认不得使用 `primary` 或自身前景色临时生成悬停背景。亮色主题统一以
黑色 `stateLayer`、暗色主题统一以白色 `stateLayer` 叠加低透明度；只有选中态
等确实表达强调语义的状态才使用主题色。控件实例可以通过自身的
`overlayColor` 显式覆盖。

### 系统字体

- 默认主题不打包或指定 Roboto 等 Flutter 示例字体，统一使用运行平台的系统 UI 字体。
- Windows 优先使用 `Microsoft YaHei UI`，并回退到 `Microsoft YaHei`、`Segoe UI`，保证中文显示稳定。
- Android 使用系统 `sans-serif`，Apple 平台使用系统 UI 字体并以 `PingFang SC` 作为中文回退。
- 业务需要品牌字体时，通过 `HyperThemeData.copyWith(textTheme: ...)` 显式替换，不在控件内部指定字体族。

### 语义字号

字号由 `HyperTypographyScheme` 集中定义，并通过 `HyperThemeData.typography`
全局提供。默认场景为：展示 48/40/36、页面标题 32、区块标题 24、小节标题
20、强调正文 18、正文 16、辅助正文 14、控件文字 16、标签 14、注释 12。

字号是明确逻辑像素，不是密度或缩放系数。修改 `body` 只修改正文，不得按比例
联动标题、控件或注释。应用可以替换整套规范，也可以通过 `copyWith` 精确覆盖
单个场景；系统无障碍文字缩放仍由 Flutter 平台能力负责。

### 渐进式 API

API 按以下层级设计：

1. 默认构造器满足最常见场景。
2. 少量语义属性满足尺寸、variant 和状态调整。
3. 控件主题满足一类控件的统一定制。
4. controller、受控状态和 builder 只用于高级交互。
5. 自定义渲染插槽只在现有语义属性无法满足时使用。

不得为了高级扩展能力增加普通用法的必填参数。也不得通过大量相互冲突的布尔参数实现样式组合；视觉类型使用强类型 variant，尺寸使用强类型 size，状态使用统一状态模型。

### 全库变体规范

大部分控件都应在设计阶段检查是否存在稳定、常用且语义明确的视觉或行为变体。变体用于提供开箱即用的成套默认值，同时保留逐项精确覆盖能力。

- 每个控件定义自己的强类型变体，例如 `HyperButtonVariant`；不建立一个所有控件共用的 `HyperVariant` 枚举。
- 对外优先使用 `.xx` 命名构造器选择内置变体，例如 `HyperButton.filled(...)`、`HyperButton.outlined(...)` 和 `HyperButton.ghost(...)`，日常使用不要求手动传 variant 枚举。
- 命名构造器只负责确定变体默认值，必须继续公开该控件适用的显式覆盖属性，不能形成能力不同的多套实现。
- 不同控件可以具有名称相同但含义独立的变体，修改按钮的 outlined 配置不得影响卡片、输入框或菜单。
- 变体只是一组默认配方，不是新的控件类型，也不得隐藏倍率缩放或修改调用方显式尺寸。
- 变体、尺寸、交互状态、异步状态和内容布局应保持正交，避免为所有排列组合创建构造器或类。
- 内部使用控件自己的强类型枚举完成主题解析；特殊外观使用控件实例属性或对应控件主题完成，不通过无限扩展枚举解决。
- 当一个控件的视觉字段较多时，可以定义该控件私有或公开的 `HyperXxxStyle` 值对象，但不得提前建立包含所有公共视觉属性的万能样式对象。
- 切换变体时默认保持控件外部尺寸稳定；确实需要不同尺寸时必须由显式 size 或宽高属性表达。
- 每个变体都需要在该控件的 Demo 中并列展示，并至少测试默认值、主题覆盖和实例覆盖。

单个视觉属性按以下顺序解析：

```text
控件实例显式属性
→ 控件主题中所选变体的详细属性
→ 控件主题的公共默认属性
→ 全局基础主题中该属性允许使用的回退值
→ 组件库内置的变体默认配方
```

内置变体默认配方可以引用解析后的主题色、基础圆角和基础动画，但只能读取全局基础主题，不能读取其他控件的主题。所有字段逐项回退，不能因为实例覆盖了一个字段就丢失其余主题字段。

### 便捷能力

- Dialog、Toast、Menu、BottomSheet 等提供基于 `BuildContext` 的简洁展示入口，内部仍使用统一悬浮层系统。
- 表单提供字段注册、校验、提交和错误定位的统一容器，减少业务层样板代码。
- 主题、异步状态和交互状态提供通用解析工具，控件实现不得重复编写相同合并逻辑。
- 常见布局模式可以提供组合组件或 builder，但不得限制基础 Widget 的自由组合。

### 简洁但不隐式失控

- 默认行为必须写入文档并保持稳定。
- 自动管理的状态和资源必须允许切换为受控模式。
- 便捷 API 不得隐藏异常、吞掉回调或绕过导航与生命周期。
- 简化代码不能以牺牲无障碍、可测试性或主题可覆盖性为代价。

## 控件组织

- 简单控件采用一个控件一个 Dart 文件。
- 复杂控件可以采用一个控件一个独立目录，并在目录内拆分状态、布局和渲染等实现。
- 不在同一个文件中混放多个无关控件。
- 每个控件都必须有与之对应的独立主题文件。

## 控件实现策略

控件绘制优先采用现有基础控件组合实现，而不是从零开始完整自绘。

### 实现优先级

```text
Flutter 基础 Widget 组合
→ 复用现有行为并定制局部视觉
→ CustomPainter 或 RenderObject 局部自绘
→ 仅在确有必要时完整自定义渲染
```

### 组合原则

- 优先使用 Flutter Material 和基础 Widget 的公开能力自由组合，不复制它们已经稳定提供的布局、手势、焦点、语义和绘制逻辑。
- 能由一个 `Container` 同时完成约束、尺寸、内外边距、对齐、背景、渐变、边框、圆角和阴影时，优先只使用这一层，不拆成多个等价包装。
- 能用一层解决的问题不得为了“架构统一”无条件增加 `Padding`、`DecoratedBox`、`ClipRRect`、`Stack` 或另一个 Hyper 控件。
- 优先使用 `Row`、`Column`、`Stack`、`Flex`、`Padding`、`Align`、`ConstrainedBox` 等布局能力。
- 优先复用 `Text`、`Icon`、`Image`、`DecoratedBox`、`ClipPath` 等基础显示能力。
- 优先复用 Flutter 的手势、焦点、快捷键、语义化、文本编辑、滚动和 Overlay 基础设施。
- 可以组合 Material 或 Cupertino 控件的成熟行为，但最终视觉和主题必须服从 Hyper 主题体系。
- 组合实现也必须接入统一的手势、动画、悬浮层、尺寸和状态体系。
- 不复制或修改 Flutter SDK 的私有控件源码作为长期实现。

### 组合层级预算

- 常规表面目标为一个 `Container` 或等价的单层基础 Widget。
- 只有单层无法表达的独立能力才增加一层，例如背景模糊、语义、焦点、手势或动画。
- 同一职责不得重复包装，例如一个控件不能同时使用两层圆角裁切或两层只为 padding 存在的 Widget。
- 裁切系统由形状边界统一管理。一个控件的同一绘制分支最多主动增加一层裁切；内部组合部件不得各自再次裁切同一边界。
- `Container.clipBehavior` 已能完成 Decoration 裁切时，不再额外套 `ClipRRect`。
- 玻璃材质为限制 `BackdropFilter` 采样范围允许增加一次必要裁切；普通和半透明材质默认不裁切。
- `Stack` 只用于真实叠层需求，例如状态层、进度背景或独立色调层，不能代替普通背景 Decoration。
- 公共控件开发完成后应检查 Widget 层级；可以安全合并的等价包装必须在提交前合并。

### 自绘边界

以下情况可以使用局部自绘：

- 基础控件无法表达的特殊形状、渐变边框或复杂进度轨道。
- 需要精确控制像素、路径或绘制性能的视觉效果。
- 使用基础控件组合会造成明显过度嵌套或持续性能问题。

自绘只负责确有必要的视觉部分。语义、焦点、键盘、鼠标、触摸和无障碍行为仍应尽量使用 Flutter 的现有基础能力。采用自绘前应确认组合方案无法满足需求，并为自绘区域增加对应测试。

## 纯色与渐变填充

纯色和渐变色属于统一的基础填充能力。能够设置背景纯色的容器、表面和视觉组件，原则上也必须支持渐变填充，不能由每个控件单独实现渐变逻辑。

### 基本规则

- 提供统一的填充抽象，例如 `HyperFill`，用于表达纯色和渐变。
- `HyperContainer`、表面、按钮、卡片、输入框背景及其他适合填充的组件复用同一套解析和绘制能力。
- 继续提供符合 Flutter 使用习惯的 `color` 和 `gradient` 便捷属性。
- 同一层级同时设置 `color` 和 `gradient` 时，`gradient` 优先，`color` 可以作为渐变不可用时的回退色。
- 渐变支持 Flutter 原生 `Gradient`，包括线性、径向和扫描渐变，不另造不兼容的渐变类型。
- 渐变必须正确服从圆角、形状、裁切、透明度、交互状态层和边框。
- 主题可以为全局或单类控件配置默认填充，控件实例仍可覆盖。

填充解析优先级：

```text
控件实例 gradient
→ 控件实例 color
→ 控件主题 fill
→ 全局基础 fill
→ 组件库内置默认 fill
```

### 状态与动画

- 默认、悬停、按压、聚焦、选中、禁用、loading、success 和 error 状态可以使用不同填充。
- 纯色到纯色、渐变到渐变以及纯色到渐变的切换应由统一动画系统处理。
- 渐变插值要求类型、颜色数量或色标兼容；无法安全插值时采用统一的交叉淡入淡出策略。

## 表面材质系统

### 全局反色与前景对比

浅色玻璃、深色渐变和动态材质不能继续使用固定前景色。`HyperContrastThemeData` 为所有适用控件提供统一策略：

- `standard`：保留控件主题或实例指定的前景色，作为默认兼容行为。
- `adaptive`：根据最终填充与页面画布合成后的亮度，在明确的浅色和深色前景之间选择对比度更高者。
- `inverted`：明确翻转当前前景的明暗方向，适合特殊区域或设计效果。
- 渐变使用色标平均值估算；半透明颜色先与画布背景合成。
- 无法获知真实 backdrop 时允许传入明确 `backgroundLuminance` 提示，不同步读取屏幕像素。
- 实例或控件主题可通过同名 `contrastMode` 覆盖全局策略。
- 反色只影响适用的前景、图标和进度颜色，不反转图片、业务语义色或整棵 Widget 树的 RGB。
- disabled、error、success 等语义状态仍优先遵守状态系统；高对比度模式后续在同一解析层扩展。

HyperOS 官方公开介绍中包含高级材质渲染、自然渐变模糊，以及会根据内容调整通透度的柔光玻璃。Lemon UI 前期将材质作为跨控件基础能力设计，但不复制系统私有算法或假定所有设备都能承担实时模糊。

### 材质与变体正交

- 控件变体描述控件语义和默认视觉，例如 `HyperButton.outlined`。
- 表面材质描述背景的合成方式，例如普通实色、半透明、毛玻璃和柔光玻璃。
- 材质不是每个控件重复实现的 variant；适用控件通过同名 `material` 属性和主题字段选择。
- 同一个 filled、outlined 或 dialog 变体可以使用不同材质，不为排列组合创建新控件。
- 材质只影响背景合成、模糊、色调、光影和边缘表现，不得暗中改变宽高、内边距、圆角或布局约束。

### 基础类型

计划提供以下基础 API：

```dart
enum HyperMaterialQuality { standard, advanced }

HyperSurfaceMaterial.solid(...)
HyperSurfaceMaterial.translucent(...)
HyperSurfaceMaterial.frostedGlass(...)
HyperSurfaceMaterial.softLightGlass(...)
```

- `standard` 使用普通填充、渐变、边框和阴影，不创建 backdrop 模糊层。
- `advanced` 允许背景模糊、饱和度、亮度、色调、自适应通透度、边缘高光和柔光层。
- 不提供根据设备性能偷偷切换质量的隐式模式。设备主题可以明确选择质量，实例也可以明确覆盖。
- `HyperSurfaceMaterial` 是不可变值对象，支持 `copyWith`、`merge`、相等比较和可安全字段的 `lerp`。

### 显式材质属性

材质在适用时至少考虑以下字段：

- 基础 `HyperFill`、叠加色和前景对比策略。
- `blurSigmaX`、`blurSigmaY` 和明确的 backdrop 开关。
- 饱和度、亮度、对比度和色调强度。
- 内容相关通透度的最小值、最大值和采样策略；默认实现不能同步读取昂贵像素数据。
- 边缘高光颜色、宽度、方向和强度。
- 内外阴影、柔光渐变和可选噪点纹理强度。
- 动画时长、曲线以及交互光效是否启用。
- `fallback` 普通材质，用于不支持模糊、减少透明度或性能受限的场景。

并非所有字段都必须由第一版实现，但类型设计应预留扩展位置，且未实现字段不得以无效果参数提前公开。

### 全局和局部配置

```text
控件实例 material
→ 控件主题的变体 material
→ 控件主题公共 material
→ 局部 HyperMaterialTheme
→ HyperThemeData.materialTheme
→ 内置普通材质
```

- `HyperMaterialThemeData` 设置全局材质质量、默认玻璃参数和降级策略。
- 控件主题仍拥有最终的该控件材质配置，避免所有控件被同一种玻璃参数强制绑定。
- 普通模式必须始终可用，并作为默认和最终回退。
- 应用可以在一个子树中使用 `HyperMaterialTheme` 切换普通或高级材质。

### 性能与降级规则

- 仅在确实需要读取背后内容时使用 Flutter `BackdropFilter`；普通透明填充不得创建模糊层。
- 模糊区域必须先裁切到实际形状，禁止对整屏或不可见区域进行无界模糊。
- 相邻或嵌套玻璃表面应尽量共享过滤结果或避免重复 backdrop，不能每层无条件增加一次模糊。
- 滚动列表中的大量玻璃单元默认降级为半透明材质；需要逐项模糊时必须显式开启。
- `MediaQuery.disableAnimations` 关闭材质动态光效；减少透明度策略启用时使用材质的 `fallback`。
- Web、低性能设备或渲染后端不支持目标效果时必须稳定降级，不能出现纯透明导致文字不可读。
- 材质切换不得造成控件尺寸变化；无法安全插值的滤镜在中点离散切换或交叉淡入淡出。

### 可读性与无障碍

- 玻璃表面必须具有明确的前景颜色和最低可读性保障，不能只依赖背后内容碰巧较暗或较亮。
- 自适应通透度属于材质算法，不得改变业务颜色语义。
- 高对比度或减少透明度模式优先使用不透明 fallback。
- 焦点、错误、选中和 loading 状态仍由控件状态系统表达，材质不能吞掉状态边框和语义色。
- 系统要求减少动画时，填充立即切换到最终状态。

### 性能与降级

- 普通渐变优先使用 Flutter 的 `BoxDecoration`、`DecoratedBox` 等基础能力。
- 不为常规渐变引入 Shader 或自定义 RenderObject。
- 手表、低性能设备或复杂列表中应避免默认启用高成本动态渐变。
- 动态渐变必须在不可见、应用失焦或减少动画时暂停或降级。

## 主题层级

Lemon UI 的主题分为三个配置层级：

1. 控件实例属性：只影响当前控件实例。
2. 控件全局主题：统一配置某一类控件。
3. 全局基础主题：配置整个组件库共用的基础属性，例如主题色、圆角、间距、字体、边框、阴影、动画和控件尺寸。

当以上层级都未提供某个属性时，使用组件库内置默认值。

## 属性优先级

所有控件必须采用统一的属性解析顺序：

```text
控件实例属性
→ 控件全局主题
→ 全局基础主题
→ 组件库内置默认值
```

示例：

```dart
final radius = widget.radius
    ?? componentTheme.radius
    ?? theme.radius
    ?? HyperDefaults.radius;
```

控件实现不得绕过这个优先级，也不得在控件内部散落无法通过主题覆盖的视觉常量。

## 全局尺寸

具体 token、各终端默认高度、圆角和命中区域以 [尺寸规范](size-specification.md) 为准。

总主题必须支持统一修改控件的基本尺寸，包括：

- 默认控件高度。
- 小型、标准和大型等语义尺寸。
- 控件的最小宽度与最小高度。
- 内边距、图标尺寸以及图标和文字之间的间距。
- 最小触控区域。

全局基础主题通过 `HyperSizeScheme` 提供尺寸配置。控件主题可以覆盖某一类控件的尺寸，控件实例属性可以覆盖单个实例。

高度等尺寸属性仍遵循统一优先级：

```text
控件实例高度
→ 控件全局主题高度
→ 全局基础主题默认高度
→ 组件库内置默认高度
```

视觉高度和最小触控区域必须分别配置。应用可以缩小控件外观，但在触控设备上仍应保留足够的可点击范围。固定高度不得阻止系统文字缩放；当内容无法容纳时，控件应根据约束扩展或采用对应的布局策略，而不是裁切文字。

## 统一基础能力

手势、悬浮层和动画属于组件库的共享基础能力，必须统一管理。控件负责声明交互意图和所需参数，不应各自重复实现完整的底层机制。

### 手势与交互

- 统一处理点击、双击、长按、拖动、悬停、按压、焦点和键盘激活。
- 统一维护默认、悬停、按压、聚焦、选中、禁用和加载等交互状态。
- 统一处理鼠标、触摸、手写笔和键盘之间的输入差异。
- 点击反馈、焦点反馈、光标和触觉反馈由共享交互层控制。
- 控件可以覆盖允许的手势参数，但不得改变公共状态语义。
- 交互层必须保留 Flutter 的语义化与无障碍能力。

### 悬浮层

- Tooltip、Menu、Popover、Dropdown、Toast、Dialog 等统一通过悬浮层服务承载。
- 统一管理插入、定位、锚点跟随、层级、遮罩、焦点、点击外部关闭和返回键关闭。
- 统一处理多个悬浮层的堆叠顺序及互斥规则。
- 悬浮层的颜色、圆角、阴影、模糊、间距和进出动画由全局主题控制。
- 控件只发起打开、更新和关闭请求，不直接维护全局 `OverlayEntry`。

### 动画

- 动画是组件库的基础能力，不是可选附加功能。所有适合过渡的视觉状态变化默认必须使用统一动画。
- 统一定义动画时长、曲线、弹簧参数、位移、缩放、淡入淡出和状态切换规则。
- 控件主题可以覆盖某类控件的动画，控件实例可以覆盖单次动画参数。
- 全局支持减少动画和关闭非必要动画。
- 相同语义的状态变化必须使用一致的动画规范。
- 动画控制器的生命周期由共享实现或控件内部安全管理，不向普通调用方暴露不必要的细节。

必须覆盖的动画场景包括：

- hovered、pressed、focused、selected、disabled 等交互状态切换。
- loading、success 和 error 等异步状态切换。
- 颜色、边框、圆角、阴影、透明度和尺寸等主题属性变化。
- Tooltip、Menu、Popover、Toast、Dialog 等悬浮层的进入和退出。
- 展开、折叠、页面切换、选中项移动和进度变化。
- `HyperThemeData` 或局部组件主题更新时的主题过渡。

主题数据对象必须提供 `lerp`，以保证动态主题切换时能够连续插值。无法直接插值的属性应定义明确的切换策略，不能由各控件自行产生不一致的跳变。

动画不得影响控件的最终状态和业务回调时序。动画被关闭或减少时，控件仍必须立即进入正确状态，并保留必要的状态反馈。持续动画在控件不可见、应用失焦或系统要求减少动画时应暂停或降级。

手势、悬浮层和动画的配置同样遵循以下优先级：

```text
控件实例配置
→ 控件全局主题
→ 全局交互、悬浮层或动画主题
→ 组件库内置默认值
```

## 普通模式与异步模式

具备操作、加载或数据交互能力的组件必须同时支持普通模式和异步模式。两种模式使用同一个公开控件，不为异步模式复制一套 `AsyncHyperXxx` 控件。

### 普通模式

- 接收同步值、状态和回调。
- 回调执行结束后立即恢复正常交互。
- 适用于本地状态变更和无需等待的操作。

### 异步模式

- 支持返回 `Future` 的操作回调，或接收外部管理的异步状态。
- 统一表达 idle、loading、success 和 error 状态。
- 加载期间可以显示进度、状态文字或保留原内容。
- 支持成功、失败、重试和取消意图；普通 `Future` 不应被描述为可强制取消。
- 异步完成时必须检查控件生命周期，不能更新已经销毁的状态。
- 异步状态的颜色、尺寸、进度样式和动画可以通过对应控件主题及总主题统一配置。

### 状态管理方式

异步组件应支持以下两种方式：

1. 便捷模式：调用方传入异步回调，由控件管理局部 loading、success 和 error 生命周期。
2. 受控模式：调用方传入统一的 `HyperAsyncState<T>`，由外部状态管理方案控制状态和数据。

组件库不得强制依赖特定的第三方状态管理框架。

### 并发策略

异步操作统一支持以下策略：

- `ignoreWhileRunning`：执行期间忽略重复触发，作为普通操作控件的默认值。
- `latestWins`：只接受最后一次操作结果，适用于搜索和异步校验。
- `sequential`：按触发顺序逐个执行。
- `concurrent`：允许多个独立操作同时执行。

旧异步操作即使较晚完成，也不得覆盖已生效的新状态。

### API 约束

- 普通模式和异步模式保持一致的布局、语义和主题解析规则。
- loading、success 和 error 属于状态，不属于视觉 variant。
- 异步模式不能改变既有同步 API 的含义。
- 并非所有纯展示组件都需要异步回调；它们只需能够展示外部传入的异步状态或占位内容（如适用）。

## 按钮组合与变体规范

`HyperButton` 使用一个轻量核心覆盖常用按钮组合，不为 filled、outlined、ghost
等纯视觉差异创建多个状态类或重复组件。变体只提供一组开箱即用的默认值，最终仍解析为
按钮自己的显式视觉属性。

### 内容形式

- 纯文字：通过 `child` 传入 `Text`，不限制文字组件的二次定制。
- 图标加文字：各变体构造器直接接受可选 `icon`、`label` 和图标位置；也允许通过任意 `child` 自由组合，避免产生 `filledIcon`、`outlinedIcon` 等大量组合构造器。
- 纯图标：使用独立的 `HyperIconButton`，以便正确处理方形约束、圆形外观、tooltip 和无障碍标签。
- 任意内容：默认构造允许传入任意 `child`；复杂布局由调用方使用 Flutter 原生组件组合。
- 前置图标和后置图标都允许使用，但不内置无限的内容槽位；更复杂的内容直接使用 `child`。

### 视觉变体

首批通过 `HyperButton.filled`、`.tonal`、`.outlined`、`.ghost`、`.text`
和 `.gradient` 命名构造器提供视觉变体。其中：

- `outlined` 默认透明背景并显示边框。
- `ghost` 默认无边框，仅在悬停、聚焦或按压时出现轻量状态背景。
- `text` 保持最小视觉装饰，适合行内操作。
- `gradient` 仍使用统一的 `HyperFill`，不是独立按钮实现。
- 变体不得覆盖实例显式传入的背景、前景色、边框、阴影、圆角、字体、内边距、高度或宽度。
- `HyperButtonThemeData` 可以分别配置各变体的默认视觉，但修改按钮主题不得影响其他控件。

### 进度表现

- 异步 loading 默认使用尺寸明确的环形进度指示器。
- 支持将进度显示为内容前置、内容替换、按钮底部线性进度条或背景填充进度。
- 确定进度使用显式 `double? progress`，有效范围为 `0.0` 到 `1.0`；未知进度使用不确定动画。
- 进度条只负责表现，不成为第二套异步状态来源；异步状态仍由按钮统一管理或由外部受控状态提供。
- 底部进度条和背景进度不得改变按钮外部宽高，并应受到按钮自身形状裁切。
- 进度颜色、轨道颜色、厚度、位置和动画可由实例或 `HyperButtonThemeData` 显式指定。

### API 轻量化边界

- 常见组合提供便捷构造；罕见组合使用 `child`、`Stack`、`Row` 等 Flutter 原生组件完成。
- 背景、边框和阴影使用按钮自己的视觉解析结果绘制，不通过 `HyperContainer`、`HyperCard` 的主题间接继承。
- 核心实现复用 `HyperPressable` 的交互状态，不再次包装或复制手势识别逻辑。
- loading、success、error 和 disabled 是状态；filled、outlined、ghost 等是视觉变体，两者保持正交。

## 按钮异步规范

所有按钮类操作控件必须支持异步模式，包括 `HyperButton`、`HyperIconButton` 以及后续的按钮变体。

### 回调

- 同步和异步模式统一使用 `FutureOr<void> Function()? onPressed`。
- 回调返回 `void` 时按普通模式执行，不进入持续 loading 状态。
- 回调返回 `Future<void>` 时由按钮自动进入异步模式，并在 Future 完成后退出 loading 状态。
- `onPressed` 为 `null` 时遵循 Flutter 原生语义，按钮处于禁用状态。
- 受控模式可以通过外部 `HyperAsyncState` 指定按钮当前状态。

示例 API：

```dart
HyperButton(
  onPressed: () async {
    await save();
  },
  child: const Text('保存'),
)
```

### 加载行为

- 异步任务开始后，按钮自动进入 loading 状态。
- 回调的同步异常和 Future 的异步异常必须进入同一套错误处理流程。
- 按钮通过回调实际返回值判断本次调用是否异步，不要求调用方额外设置异步开关。
- 默认使用 `ignoreWhileRunning`，加载期间阻止重复触发。
- loading 时保持按钮原有宽高，避免内容切换导致布局跳动。
- 支持保留原内容、替换为加载文字或显示进度指示器。
- 加载状态和普通 disabled 状态必须在内部语义上区分。
- 屏幕阅读器应能获知按钮正在执行操作。

### 完成与错误

- 任务成功后恢复正常状态，并可选择显示短暂 success 状态。
- 任务失败后恢复可操作状态，并可选择显示短暂 error 状态。
- 错误默认交给调用方处理；也可以通过统一错误回调或反馈服务处理。
- 不得静默吞掉异常。
- 控件销毁后，异步任务完成不得继续更新控件状态。

### 可配置项

按钮实例、`HyperButtonThemeData` 和 `HyperThemeData` 可以配置：

- 默认异步并发策略。
- 加载指示器的尺寸、颜色和位置。
- 是否保留按钮文字。
- loading、success 和 error 的状态文字或图标。
- 成功与失败反馈的停留时间和动画。
- 加载期间是否允许取消；仅在调用方提供取消能力时启用。

配置优先级仍为：

```text
按钮实例配置
→ HyperButtonThemeData
→ HyperThemeData
→ 组件库内置默认值
```

## 表单尺寸稳定性

表单及输入类控件应尽量在状态切换过程中保持尺寸稳定，避免校验、加载和辅助内容变化导致页面频繁跳动。

### 基本规则

- 输入框在默认、聚焦、填写、校验中、成功、错误和禁用状态之间切换时，主体高度应保持一致。
- 边框宽度变化不得改变控件的外部尺寸；焦点边框和错误边框应向内绘制或预留空间。
- 前缀、后缀、清除按钮、密码可见按钮和加载指示器应使用稳定的约束尺寸。
- loading 图标替换普通图标时不得改变输入区域宽度。
- label 浮动、placeholder 消失和文字变化不应造成输入框整体高度跳动。
- 表单提交期间的只读或禁用状态不得改变现有布局。

### 提示与错误区域

- helper、error、success 和 validating 信息使用统一的消息区域。
- 默认可以为消息区域预留最小高度，以保证状态切换时相邻字段位置稳定。
- 应允许通过主题关闭预留空间，适用于更重视紧凑布局的场景。
- 多行错误信息可以向下扩展，但不得覆盖字段或裁切关键内容。
- 状态信息切换时优先进行内容淡入淡出，而不是反复改变整个字段高度。

### 尺寸策略

表单主题应统一配置：

- 单行输入框的默认高度和最小高度。
- 多行输入框的最小行数、最大行数和内容约束。
- label、输入内容和消息区域的间距。
- 前后缀区域尺寸。
- 消息区域是否预留空间及其最小高度。
- 手机、平板、桌面和手表策略下的默认尺寸。

控件实例仍可覆盖这些配置，优先级为：

```text
表单控件实例配置
→ 对应表单控件主题
→ 全局表单与尺寸主题
→ 组件库内置默认值
```

尺寸稳定不等于强制固定高度。系统文字放大、内容换行或多行错误确实需要更多空间时，控件必须安全扩展，不能为了维持高度而裁切内容或破坏无障碍体验。

## 总主题

- 使用一个总主题对象集中承载全局基础主题和各控件主题。
- 应用可以通过总主题一次性配置整个组件库。
- 控件仍可通过实例属性覆盖总主题中的对应配置。
- 主题对象应保持不可变，并提供 `copyWith`。
- 接入 Flutter 主题系统时，总主题应支持 `ThemeExtension`；需要主题动画时应提供插值能力。

## 约束

- 控件文件负责公开 API、行为和渲染，不承担全局主题配置。
- 控件主题文件负责该类控件可复用的默认外观配置。
- 全局基础主题只存放跨控件共享的设计属性，不存放某个控件独有的配置。
- 新增控件时，控件文件、控件主题文件和总主题注册应一并完成。

### 实例属性与主题属性镜像

控件中公开的样式属性应尽量在对应的 `HyperXxxThemeData` 中提供同名、同类型、同语义的配置。调用方从单个实例迁移到全局控件主题时，不应重新学习另一套命名或转换数值。

- 背景、前景色、填充、边框、阴影、字体、圆角、内外边距、间距、宽高、约束、图标尺寸、状态样式和动画参数等，应同时支持实例配置与控件主题配置。
- 控件主题的公共样式和各变体样式使用同一种 `HyperXxxStyle` 值类型；实例公开的便捷属性也使用与该样式字段一致的 Flutter 原生类型。
- 主题与实例中的对应字段必须保持同名。例如实例为 `borderRadius`，主题中不得改名为 `cornerRadius`。
- 每个样式字段都允许为 `null`，表示继续向下一层回退；不得用特殊数值、透明色或空对象表示“继承”。
- `copyWith`、`lerp`、相等比较、状态解析和逐字段合并在控件主题中使用统一模式实现。
- 新增或删除实例样式属性时，必须同时检查控件主题、变体样式、Demo 和测试，防止主题能力落后于实例 API。

以下运行时属性通常不进入主题：

- `key`、`child`、业务数据和 builder。
- 点击回调、状态变化回调及其他业务事件。
- controller、focusNode、scrollController 等具有所有权和生命周期的对象。
- 语义标签中的具体业务文案。

行为策略只有在适合整类控件统一配置时才进入主题，例如动画时长、反馈开关、异步并发策略；具体回调和运行时对象仍只属于实例。

以按钮为例，统一设置方式保持一致：

```dart
HyperButton.outlined(
  height: 48,
  borderRadius: BorderRadius.circular(16),
  border: const BorderSide(width: 1),
  onPressed: save,
  child: const Text('保存'),
)

HyperButtonThemeData(
  outlined: HyperButtonStyle(
    height: 48,
    borderRadius: BorderRadius.circular(16),
    border: const BorderSide(width: 1),
  ),
)
```

实例便捷属性最终合并到同一个控件样式解析过程，不能维护一套与主题分离的绘制分支。

### 继承、显式清除与 `copyWith`

样式系统必须区分“未指定，继续继承”和“显式移除当前效果”。

- `null` 统一表示未指定并继续向下一层解析。
- 使用类型明确的空值移除效果：`HyperFill.none`、`BorderSide.none`、空阴影列表和 `EdgeInsets.zero`。
- 透明色是实际颜色，不等于无填充；零宽边框也不应被内部重新替换成主题边框。
- `copyWith` 必须区分参数未传入与显式传入 `null`。实现使用内部哨兵值或等价机制：未传入时保留原值，显式 `null` 时恢复继承。
- `merge` 只应用来源中非空的字段；明确的 none、空列表和零值属于有效覆盖，不能在合并时忽略。
- 每个样式类型都必须测试继承、显式清除、零值、空列表和 `copyWith` 恢复继承。

### 状态样式逐字段解析

状态不能通过整体替换样式对象实现，否则一个按压背景可能意外清除实例字体、边框或尺寸。每个属性独立按以下顺序解析：

```text
实例的当前状态属性
→ 实例基础属性
→ 局部控件主题中变体的当前状态属性
→ 局部控件主题中变体的基础属性
→ 全局控件主题中变体的当前状态属性
→ 全局控件主题中变体的基础属性
→ 控件主题公共状态属性
→ 控件主题公共基础属性
→ 全局基础主题
→ 内置变体默认值
```

- 多状态同时存在时使用 `HyperControlState` 的统一优先级逐字段选值。
- 实例基础属性的优先级高于主题状态属性；实例显式设置背景后，主题按压背景不得将其替换。
- 默认悬停和按压反馈优先使用独立 `stateOverlayColor` 等状态层属性，使自定义背景仍能保留反馈。
- loading、success 和 error 只参与状态解析，不改变控件所选变体。

### 组合参数与扩展出口

- 同时提供 `child` 与 `label`、`icon` 等便捷内容参数时必须通过断言拒绝歧义组合。
- 图标方向使用 `AlignmentDirectional`、`EdgeInsetsDirectional` 或明确的方向枚举，自动支持 RTL。
- 高频样式直接暴露为实例参数；完整或低频配置收敛到对应 `HyperXxxStyle`，直接参数优先于 `style`。
- 特殊内容优先允许任意 `child` 组合；仅在组合无法访问控件内部状态时提供 `foregroundBuilder`、`backgroundBuilder` 或状态 builder。
- builder 是高级扩展出口，不能成为普通样式设置的唯一方式。

### 视觉尺寸与可操作区域

- 显式视觉宽高不得被组件库偷偷扩大或缩放。
- 需要更大的触控区域时使用独立、显式的 `minimumTapTargetSize` 或命中区域配置，不改变视觉尺寸语义。
- 桌面鼠标控件可以使用较小视觉尺寸；触摸端默认值仍应符合无障碍建议。
- 文字缩放、RTL、高对比度和系统减少动画必须纳入控件验收，不通过固定裁切隐藏布局问题。

### 局部控件主题

需要区域级统一替换的控件提供轻量 `HyperXxxTheme`，例如 `HyperButtonTheme`。解析顺序为局部控件主题、总主题中的控件主题、全局基础主题和内置默认值。局部主题只影响子树中的同类控件，不能修改其他控件主题。

### 样式插值

- 颜色、尺寸、圆角和兼容的阴影、渐变按字段插值。
- 列表长度、渐变类型或形状结构不兼容时使用离散切换或交叉淡入淡出，不强行计算无效中间值。
- 减少动画开启时直接使用最终样式。
- 样式插值不能改变最终明确尺寸，也不能引入倍率换算。

## 控件样式的独立控制

每个控件的可配置属性必须能够独立控制。调用方修改某一个属性时，不应被迫复制整套样式，也不应意外覆盖其他已由主题提供的属性。

样式配置分为三个层级：

1. `HyperThemeData`：全局基础主题，控制所有控件共享的基本属性。
2. `HyperXxxThemeData`：指定控件的全局主题，控制该类控件的详细属性。
3. `HyperXxx` 实例属性：控制当前控件实例的详细属性。

所有属性均应逐项解析，而不是把上层样式对象整体替换掉。例如，实例只指定圆角时，背景、字体和阴影仍应继续继承控件主题或全局主题。

```dart
final background = widget.background
    ?? buttonTheme.background
    ?? theme.background
    ?? HyperDefaults.background;

final radius = widget.radius
    ?? buttonTheme.radius
    ?? theme.radius
    ?? HyperDefaults.radius;
```

### 基本可配置属性

控件在语义和结构适用时，至少应考虑支持以下属性：

- 背景：纯色、透明度、状态背景和表面材质。
- 渐变：背景渐变、状态渐变及其方向和色标。
- 阴影：颜色、模糊、扩散、偏移和多层阴影。
- 边框：颜色、宽度、样式和各交互状态下的边框。
- 颜色：前景色、文字色、图标色、强调色及各种状态颜色。
- 字体：字体族、字号、字重、字间距、行高和文本样式。
- 圆角与形状：统一圆角、各角独立圆角及适用的形状配置。
- 内边距：内容与控件边界之间的间距。
- 外边距：控件周围的便捷间距；组合与布局场景仍优先允许使用 Flutter 的 `Padding` 等原生组件。
- 尺寸：宽度、高度、最小和最大约束、图标尺寸、触控区域及语义尺寸。
- 状态样式：hovered、pressed、focused、selected、disabled、loading、success 和 error。
- 动画：时长、曲线、弹簧和样式变化的过渡方式。

状态集合统一使用 `HyperControlState` 表达。简单属性通过 `HyperStateValue<T>` 按全局优先级解析，复杂组合使用显式解析回调。默认优先级从高到低为：disabled、loading、error、success、longPressed、secondaryPressed、tertiaryPressed、pressed、dragged、selected、focused、hovered、默认值。

右键或其他辅助指针按键按下时使用 `secondaryPressed` 视觉状态。右键业务操作不放入状态对象；交互控件应独立提供 `onSecondaryTap`、`onSecondaryTapDown`、`onSecondaryTapUp` 和 `onSecondaryTapCancel`，并允许调用方据此打开统一悬浮菜单。

### 通用手势入口

`HyperPressable` 作为所有可操作控件的轻量交互底座，基于 Flutter 原生 `GestureDetector`、`MouseRegion`、`Focus`、`Actions` 和 `Semantics` 组合，不重复实现手势识别器。

- 主按键：tap、tapDown、tapUp、tapCancel。
- 双击：doubleTap、doubleTapDown、doubleTapCancel。
- 长按：longPressDown、longPressStart、longPressMoveUpdate、longPress、longPressUp、longPressEnd、longPressCancel。
- 右键：secondaryTap 及完整点击生命周期；右键长按在明确需要时扩展。
- 中键：tertiaryTap 的 down、up、cancel；中键长按在明确需要时扩展。
- 指针与键盘：enter、exit、hover、focus、键盘/遥控器激活、鼠标光标。
- 拖动仅在调用方提供对应回调时接入；不得因默认按压支持而抢占滚动手势。
- 触觉和声音反馈必须可以由主题统一开关，也允许实例显式覆盖。
- 同时提供单击和双击时，单击必须等待 Flutter 手势竞技场排除双击，不允许为了响应更快而提前触发两次业务操作。
- 双击、长按等瞬时业务事件本身不存入长期状态；仅在手势持续期间维护 `longPressed` 等视觉状态。

### 适用性原则

- 属性只在控件语义适用时提供，不要求所有控件机械地暴露全部参数。
- 纯文本或无容器结构的控件可以不提供背景、阴影或边框。
- 没有文字内容的控件可以不提供字体配置。
- 不参与外部布局的内部部件可以不提供外边距。
- 不适用的属性直接忽略于该控件的 API 设计，不提供无效果的占位参数。
- 即使某属性不作为控件实例参数公开，只要它属于该控件的稳定视觉能力，也应考虑能否通过对应的 `HyperXxxThemeData` 配置。

### 形状与裁切

- `HyperShape` 作为独立基础类型，不绑定 `HyperContainer`、`HyperCard` 等任一控件主题。
- 优先兼容 Flutter 的 `ShapeBorder`、`OutlinedBorder` 和 `Path`，避免重复实现 Material 已有的形状能力。
- 内置常规形态至少覆盖普通圆角、各角独立圆角、连续圆角、超椭圆、胶囊、圆形、椭圆和斜切角。
- 参数化异形至少覆盖三角形、菱形、规则或自定义多边形、星形、箭头、缺口、票券孔、波浪、锯齿、心形、气泡、水滴和盾牌。
- 任意异形允许通过显式 `Path`、路径构建器或可解析的矢量路径数据提供，但不得使用不透明字符串配置其他视觉属性。
- 形状负责描述边界；是否裁切由控件的 `clipBehavior` 显式决定。设置形状不得自动开启昂贵裁切。
- 同一形状应尽量同时用于背景、边框、状态层、命中区域和裁切，避免边缘不一致。
- 所有参数化图形使用明确尺寸、角数、半径、角度、凹凸深度、重复次数等属性，不依赖隐藏倍率。
- 自定义路径需要明确坐标体系（绝对坐标或归一化坐标）、尺寸适配、文字方向、填充规则和命中测试策略，并缓存可复用路径。
- 凹形、自交路径和带孔路径必须显式处理 `PathFillType`；边框绘制不能简单假设路径为凸形。
- 几何裁切应提供 `Clip.none`、`hardEdge`、`antiAlias` 和 `antiAliasWithSaveLayer`，默认不使用高成本的 `saveLayer`。
- 复杂异形需要同时测试不同宽高比、极小尺寸、RTL、动画插值、命中测试和语义边界。
- 形状主题变化需要支持插值，并允许不同类型的形状互相变换。

#### 形状变换规则

- 同类型、参数结构一致的形状直接逐参数插值，例如圆角到圆角、五角星到五角星、多边形到相同顶点数的多边形。
- 不同顶点数或不同路径命令的形状，在变换前统一为闭合轮廓并按弧长重采样，使起止轮廓拥有相同数量和顺序的控制点。
- 轮廓需要统一起点、绘制方向和闭合方式，自动选择位移最小的点对应关系，避免变形过程中扭转或翻面。
- 多轮廓和带孔形状必须按轮廓语义分别配对；无法可靠配对时不得静默生成错误形状。
- 可显式配置 `morphStrategy`：参数插值、路径重采样、交叉淡入淡出或中点离散切换。
- 可显式配置采样点数、起点对齐、旋转对齐、路径方向和填充规则；默认值只提供开箱即用行为，不隐藏修改控件尺寸的倍率。
- 动画过程中背景、边框、裁切、状态层和命中区域使用同一个当前插值路径，防止视觉和交互边界不同步。
- 高频变形缓存归一化结果，只在尺寸、形状参数或文字方向变化时重新计算路径。
- 形状变换遵守全局动画时长、曲线和减少动画设置；关闭动画时立即进入目标形状。
- 若两条路径无法安全变形，默认使用交叉淡入淡出；调用方可以明确选择中点切换，禁止不可预测的自动拓扑猜测。

### 进度形态

- `HyperProgressIndicator` 只提供统一语义和主题入口，具体视觉由线性、圆形、圆弧或蚯蚓形态分别实现。
- `HyperWormProgressIndicator` 的“蚯蚓”由头尾位置分别动画形成伸缩效果，不通过整体倍率缩放实现。
- 支持确定进度和不确定进度；确定进度必须准确反映 `value`，不确定进度使用持续循环动画。
- 必须显式配置轨道高度、前景颜色、轨道颜色、圆角、动画时长和曲线，并遵守系统减少动画设置。
- 持续动画在不可见、应用失焦或系统要求减少动画时暂停、静止或退化为低成本表现。
- 所有进度形态提供正确的无障碍进度语义；纯装饰加载效果允许显式排除语义。

### API 设计约束

- 优先使用 Flutter 已有类型，如 `Color`、`Gradient`、`BoxShadow`、`BorderSide`、`BorderRadiusGeometry`、`TextStyle`、`EdgeInsetsGeometry` 和 `BoxConstraints`。
- 常用属性可以直接暴露；大量低频属性可以收敛到强类型样式对象，但样式对象仍须支持逐字段覆盖。
- 不使用一个不透明的 `Map` 承载样式，也不依赖字符串键配置属性。
- 所有 `HyperXxxThemeData` 必须不可变，并提供 `copyWith` 和 `lerp`。
- 控件实例、控件主题与全局主题对同一属性应使用一致的类型和语义。
## 精确尺寸与禁止隐式缩放

Lemon UI 必须同时满足开箱即用和精确定制。主题可以统一替换全局效果，局部主题可以替换指定区域，控件实例可以精确覆盖单个位置；任何便捷机制都不得暗中改变显式指定的数值。

### 显式值原则

- 宽度、高度、最小和最大约束、圆角、边框宽度、间距、内外边距、图标尺寸、阴影参数及动画时长等属性均使用明确的 Flutter 逻辑像素或原生类型。
- 调用方显式传入的值就是最终目标值，组件库不得再次乘以全局 scale、density、deviceScale 或其他隐藏系数。
- `width: 100` 必须表示 100 个逻辑像素；`radius: 12` 必须表示 12 个逻辑像素。
- 控件主题中显式指定的详细值同样不得被全局缩放系统二次变换。
- 不使用 CSS 风格的隐式尺寸缩放变量，也不建立所有尺寸都依赖某个倍率的主题体系。

### 默认值与系统密度

- 屏幕像素密度、设备像素比和逻辑像素换算完全使用 Flutter 与操作系统的原生能力。
- Lemon UI 不定义 `density`、`densityScale`、`controlScale` 或类似的内部密度系数。
- 控件内部不得读取设备像素比后对宽高、圆角、间距、字体或边框进行二次缩放。
- `MediaQuery.devicePixelRatio` 仅可用于像素对齐、绘制精度或资源选择，不能用于改变控件的逻辑尺寸。
- 不提供 compact、standard、comfortable 一类会隐式改变所有尺寸的控件密度系统。
### 外部缩放控件

后期可以提供类似 `HyperScaledBox` 的显式缩放控件，用于调用方主动缩放一个完整区域，但它必须与控件主题和尺寸解析系统隔离。

- 缩放只在调用方显式包裹时生效，不得由 `HyperThemeData` 自动注入。
- 子控件不得读取缩放倍率并重新计算自身宽高、圆角、间距、字体或边框。
- 缩放控件应在外层统一处理整个子树的布局或视觉变换，避免部分属性缩放、部分属性不缩放。
- API 必须明确区分布局缩放和仅绘制变换，并说明其对布局占位、命中测试、文字清晰度及无障碍的影响。
- 缩放控件不能改变子控件显式属性的语义；子控件的 `width: 100` 在自身坐标系内仍然是 100 个逻辑像素。
- 该能力属于显式高级工具，不作为组件库默认响应式或多设备适配方案。
- 保留 small、medium、large 等尺寸系统；每一档必须映射为一套明确、独立、可检查的数值，不通过基础尺寸乘倍率生成。
- 不同控件可以为同名尺寸提供符合自身语义的明确数值，例如按钮和输入框的 small 高度可以不同。
- 显式尺寸属性优先于尺寸预设；例如同时设置 `size: small` 和 `height: 37` 时，最终高度必须是 37。
- 设备策略只能在属性未指定时选择合适的默认值，不能修改已经解析出的显式值。
- 全局基本高度变化只影响没有在控件主题或实例中指定高度的控件。
- 控件主题只覆盖对应控件，局部 `HyperTheme` 只影响其子树，全局 `HyperTheme` 作为最终公共默认来源。

解析过程必须是“选择值”，而不是“选择值后再缩放”：

```dart
final height = widget.height
    ?? buttonTheme.height
    ?? theme.controlHeight
    ?? HyperDefaults.controlHeight;
```

禁止采用：

```dart
final height = resolvedHeight * theme.scale;
```

### 全局与局部替换

- `HyperThemeData` 用于统一替换应用级基础效果。
- `HyperXxxThemeData` 用于统一替换某一类控件的详细效果。
- 嵌套 `HyperTheme` 或对应控件主题用于替换指定组件树区域。
- 控件实例属性用于替换指定位置，且优先级最高。
- 局部覆盖采用逐字段合并；未指定的字段继续继承，不要求复制整套主题。

### 字体与系统缩放

- 控件几何尺寸与系统文字缩放相互独立，不能用同一个缩放倍率处理。
- `fontSize` 表示明确的基础字号；系统 `TextScaler` 仍按 Flutter 无障碍规则作用于文字。
- 文字放大后空间不足时，布局应扩展、换行或使用明确的约束策略，不能偷偷缩小字体或整体缩放控件。
- 如业务确需固定文字比例，必须通过显式的文字缩放策略配置，而不是由主题隐式关闭无障碍缩放。

### 可预测性要求

- 所有影响绘制结果的转换规则必须有公开类型和文档，不能隐藏在内部魔法数中。
- Debug 模式应能检查控件最终解析出的主题和尺寸，便于定位值来自实例、控件主题、局部主题还是全局主题。
- Golden 测试必须覆盖显式尺寸不受设备类别和全局默认尺寸影响的场景。

## 控件视觉独立与轻量复用

每个公开控件应拥有自己的视觉属性和 `HyperXxxThemeData`。控件可以复用 Flutter 基础 Widget、无状态设计令牌和内部绘制工具，但不得依赖另一个公开控件的主题来构成自身外观。

### 核心原则

- 修改 `HyperCardThemeData` 只能影响 `HyperCard`，不能让内部碰巧使用 Card 的按钮、菜单、输入框或其他控件一起变形。
- `HyperButton`、`HyperTextField`、`HyperDialog` 等各自解析自己的背景、前景、边框、圆角、阴影、字体、间距和尺寸。
- 控件实现不得为了复用外观而在内部直接嵌套带独立全局主题的公开视觉控件。
- 全局基础主题只提供明确约定的公共回退值，例如主题色、默认字体、基础圆角和基础动画；组件主题解析后得到的最终值必须独立。
- 某个组件主题需要跟随全局基础主题时，应在属性未指定时显式回退，而不是订阅另一个组件的主题。

### 可以复用的能力

以下能力可以安全复用：

- Flutter 原生的布局、绘制、文本、焦点、手势、语义和动画能力。
- 不读取其他组件主题的内部私有绘制部件。
- `HyperFill`、边框、阴影、状态解析和动画插值等无组件归属的值对象与算法。
- 统一的手势、Overlay 和异步状态基础设施。
- 接收完整显式参数、没有自身主题继承行为的内部渲染函数。

例如，按钮和卡片可以共用背景与边框绘制算法，但按钮不能通过创建一个 `HyperCard` 来绘制按钮背景。

```text
HyperButton
├─ 解析 HyperButtonThemeData
├─ 得到完整的按钮视觉参数
└─ 调用无主题耦合的内部绘制能力

HyperCard
├─ 解析 HyperCardThemeData
├─ 得到完整的卡片视觉参数
└─ 调用同一套底层绘制能力
```

### 不允许的主题耦合

- Button 内部使用 `HyperCard`，从而意外继承 `HyperCardThemeData`。
- Dropdown 内部使用公开 `HyperDialog`，从而因 Dialog 全局主题改变尺寸。
- 多个组件共享同一个可变或万能组件样式对象。
- 修改一个具体组件主题后，影响未在 API 中声明关联关系的其他组件。
- 为减少少量重复代码而引入跨组件的视觉依赖链。

### 属性范围

控件应直接提供自身常用且有意义的详细视觉属性，即使这些属性与其他控件存在重复，例如背景、边框、阴影、圆角、文字样式、内边距和尺寸。重复的 API 字段可以接受，底层实现和类型仍应复用。

但仍不需要机械地为每个控件塞入所有公共属性：

- 属性必须对应控件实际拥有的视觉层或内部部件。
- 低频且与控件本体无关的外部变换可以由调用方显式组合。
- 外边距通常交给父布局管理，不作为所有控件的必备属性。
- 不提供没有绘制效果的占位属性。

### 外部组合的定位

`HyperSurface`、`HyperContainer` 和 Flutter 原生包装控件仍可由业务层主动组合额外效果，但它们不是其他 Hyper 控件的默认内部实现，也不会替代控件自身的视觉主题。

因此同时满足：

- 普通控件不需要层层包装即可完成常用定制。
- 高级附加效果仍可由调用方显式组合。
- 更改某个公开控件的全局主题不会意外改变其他控件。
- 底层绘制和交互实现仍可共享，避免重复维护。
## 基础视觉实现选择

大部分常规视觉属性优先使用 Flutter 原生 `Container` 及其底层组合能力实现。`Container` 只负责承载当前控件已经解析完成的视觉参数，不读取或继承其他 Hyper 控件的组件主题。

### 推荐顺序

```text
Container / DecoratedBox / Padding / ConstrainedBox
→ AnimatedContainer 或统一隐式动画部件
→ ClipRRect / ClipPath 等局部裁切
→ CustomPainter 局部特殊绘制
→ RenderObject 仅用于确有性能或布局必要的场景
```

### `Container` 适用范围

通常可以使用 `Container` 处理：

- 明确的宽度、高度及约束。
- 内边距和对齐。
- 纯色和渐变背景。
- 圆角与常规形状。
- 常规边框。
- 单层或多层 `BoxShadow`。
- 前景装饰和基础变换。

当一个控件同时需要两项以上常规视觉或布局能力时优先使用单个 `Container` 合并完成。仅需要单一背景装饰时可使用 `DecoratedBox`；仅需要间距或约束时直接使用 `Padding`、`SizedBox` 或 `ConstrainedBox`，避免无意义包装。

### 动画处理

- 简单且可由 `Decoration.lerp` 稳定插值的变化可以使用 `AnimatedContainer`。
- 复杂状态组合、不同类型渐变、特殊边框或多属性协同时，使用统一动画解析层，不依赖多个嵌套 `AnimatedContainer`。
- 动画开始前先解析当前控件自己的完整起止样式，再执行插值。
- 动画实现不得引入倍率缩放或改变显式尺寸的语义。

### 不由 `Container` 负责的能力

以下能力使用各自的 Flutter 基础设施，不塞入视觉容器：

- 点击、拖动、悬停等手势。
- Focus、快捷键和键盘导航。
- Semantics 与无障碍。
- 文本编辑、选择和输入法。
- Overlay、锚点跟随和焦点陷阱。
- 异步状态、生命周期和错误传播。

### 自绘边界

只有在 `Container`、`DecoratedBox` 和基础 Widget 无法准确表达时才使用 `CustomPainter`，例如特殊路径、非标准渐变边框、复杂进度轨道或高性能批量绘制。即使采用自绘，布局、命中测试、焦点和语义仍优先复用 Flutter 原生能力。
## 多窗口架构预留

正式版阶段加入多窗口相关控件。当前核心架构必须避免使用会阻碍多窗口的全局静态状态：主题、Overlay、焦点、导航和快捷键均通过当前窗口的 `BuildContext` 与作用域获取。

- 核心包只定义平台无关的窗口模型、作用域和 UI 协议。
- 平台窗口创建、移动、缩放和系统按钮通过可选适配层实现。
- 每个窗口拥有独立 Navigator、Overlay、FocusScope 和生命周期。
- 应用级主题可以共享默认值，窗口级和局部主题可以独立覆盖。
- 控件不得缓存来自其他窗口的 `BuildContext` 或继承主题解析结果。
- 多窗口不改变显式尺寸原则，也不引入密度倍率缩放。
- 正式实现前需要分别验证 Windows、macOS、Linux，以及平台支持时的平板多场景能力。
## Demo 驱动验收

每实现一步都必须在 Example 中提供可运行、可直观看到效果的 Demo。Demo 是完成标准的一部分，不是发布前再补的附属内容。

- 视觉属性必须通过并排或分组样例展示默认值、主题值和实例覆盖值。
- 状态、动画、异步和 Overlay 必须提供可操作入口。
- 无直接视觉输出的基础类型必须通过最小视觉载体呈现解析结果。
- Demo 不依赖真实网络或外部服务，异步和错误场景使用可重复的本地模拟。
- 每个 Demo 至少有启动测试；关键交互增加 Widget 测试。
- 没有完成 Demo 和对应测试的控件不得在组件目录中标记为 `[x]`。

### Demo 控件替换规则

- Example 最终必须由已经实现的 Hyper 控件组成，包括菜单、切换器、列表、弹层、提示、分页等辅助界面，不只替换被演示的主控件。
- 某类 Hyper 控件完成时，同一步检查并逐步替换 Example 中对应的 Material/Cupertino 控件；不得把替换工作无限期留到最后集中处理。
- 尚无 Hyper 实现时允许暂用 Flutter 原生控件，但它只是可追踪的临时占位，视觉必须服从 Hyper 全局颜色、字号、尺寸和动画主题。
- 原生控件只在“兼容性对照”或“底层组合实现”场景保留；作为对照时必须在界面文案中明确标识，不能与正式 Hyper 示例混淆。
- 替换辅助控件后必须更新其 Demo 测试，验证菜单导航、交互和可访问语义没有退化。
- 每完成一个新控件，验收清单必须包含“搜索 Example 中同类原生控件并处理”这一项。

- API 文档注释、必要的实现注释、测试用例描述和 Example 界面文案统一使用中文。
- 注释应说明设计意图、边界和非显然行为，不逐行翻译代码或添加无意义注释。
- 标准库、Flutter 类型及无法准确翻译的技术术语保留原名。
